## 设计层面总体判断（前置）

本稿件最值得肯定的设计特征是「前瞻性冻结 + 三套对照分工」：阴性对照（BLD/BRN，检验组织特异性）、匹配零分布（检验统计量校准）、阳性对照（检验管线灵敏度），三者缺一不可（协议 §10.5）。这一框架本身是预防 HARKing 与选择偏倚的强约束，且稿件大体遵守。但「冻结」与「结果出来后的重定位」之间存在张力：协议 §11.1 冻结的三句核心主张中，#3（投射方法的普遍失效）被数据反向推翻，稿件改为「签名/细胞类型特异性失效」。这种重定位在科学上可辩护（数据确实显示 4/5 保留特异性），但其与 §11.1 冻结主张的关系是本评审与全组面板共同关注的核心。下面各条目在统计设计层面逐一审视，不替代对叙事诚信的整体判断。

**本评审与设计层面核心张力的接口：** 统计设计层面可以确认的是——SI_g 规则的逻辑与「1/5 失败 → 主终点 FAIL」的处理是正确且诚实的（条目 5），「4/5 保留特异性」这一数据事实经独立核验成立（速查表）。因此「重定位为签名/细胞类型特异性失效」有真实数据底座，并非凭空翻转。统计设计层面无法裁定、需由统筹评审结合叙事诚信判断的是：这一重定位相对于 §11.1 冻结主张是否已被充分、显式地交代（见条目 5 问题 5 与 §前置末段）。设计层面只要求该交代存在且诚实，而不要求回到原冻结主张。

## 评审条目（4 部分格式）

### 条目 1 — [Minor–表述]  阴性对照治理（§5.3）的「uninformative not negative」表述，与两种校准口径的混用风险

**【Problem】** 稿件用「BLD q = DRG q = 0.409（两者都不显著且相等）」来支持 Stage A 为「uninformative（不可推断）」而非「negative（阴性）」。但这一「等显著」判据在匹配口径下其实是「两者同为 null」，其力度弱于协议 §8.1 用来改判的「未分层口径下 BLD P=0.0009 ≫ DRG 匹配口径 0.102」这一更强理由。稿件必须确保不把未分层口径（0.597 / 0.0009）与匹配口径（0.102 / 0.100）混用，否则就违反了它自己声明的口径纪律。

**【Evidence】**
- 重算 `layer1_diag.json` → `stratified_vs_unstratified` → `hippo_dependent_up` / `DRG_SNI`：`MRU_stratified_space`=0.71677，`p_expression_matched`=0.10229，`q_expression_matched`=0.40916；`BLD_SNI`：`MRU_stratified_space`=0.6964，`p_expression_matched`=0.10039，`q_expression_matched`=0.40916。稿件 `manuscript.md:14`（摘要）与 `:58-59`（Stage A 节）所报 MRU 0.717 / P 0.102 / q 0.409 与 MRU 0.696 / P 0.100 / q 0.409 与 JSON 一致（四舍五入吻合）。
- 协议 `PROTOCOL_基质刚度与神经病理性痛.md` §8.1 与 §5.3 的改判原动力来自**未分层全背景口径**：BLD P=0.0009（强于 DRG 匹配口径 0.102 两个数量级）；稿件 `:59` 同时给出未分层口径 DRG P=0.597、BLD P=0.0009，并称「explicitly not the primary endpoint」。
- `q`=0.409 对 DRG 与 BLD 完全相同，是 BH 单调性向下拉平的结果：在 HD_up 的 8-contrast family 中最小两个 p 为 0.10039（BLD_SNI）与 0.10229（DRG_SNI），标准 BH 得 `q_rank2 = 0.10229×8/2 = 0.40916`，`q_rank1 = min(0.10039×8/1, 0.40916) = 0.40916`。这是两个并列最小 p 经单调校正后的同一数值，并非两个独立估计；换言之，「BLD q = DRG q = 0.409」是 BH 算法的人为结果，不应被读成「两次独立估计恰好相等」的生物学对称。

**【Why it matters】** §5.3 治理规则原文是「若阴性对照与主终点同等显著，则结论不得成立」。在匹配（主）口径下，主终点与阴性对照都是 null 且 q 相等——规则在字面上确实触发，但「uninformative」的较强依据（阴性对照比目标更显著）实际来自稿件自己声明「非主口径」的未分层数字。若读者把 0.0009 当成治理依据，就犯了稿件要避免的「混用口径」错误；若仅看匹配口径，则「两者同为不显著」本就不足以宣称任何转移结论，所谓「uninformative」在匹配口径下几乎等同于「negative + 无法区分组织」。稿件目前分开陈述两种口径，方向正确，但措辞上「equally significant」易让人误以为匹配口径下阴性对照「同等亮起」，而实际是「同等熄灭」。这是表述精确性问题，不是数据错误，但会影响读者对 Stage A 地位的准确理解。

**【Specific fix】**
- 在 Stage A 节与摘要中，将「because the negative control is equally significant」改为明确表述：「在预指定的匹配口径下，主终点（DRG P=0.102, q=0.409）与阴性对照（BLD P=0.100, q=0.409）均不显著且 q 相等；依 §5.3 等显著条款，组织特异性的正向结论无法成立，故 Stage A 为不可推断（uninformative）而非阴性证据。」并加一句：「§8.1 中 BLD 未分层 P=0.0009 ≫ DRG 的更强混杂证据来自非主口径，仅用于解释为何未分层口径被弃用，不作为本结论的治理依据。」

### 条目 2 — [Moderate–可追溯性]  置换检验有效性与「有界 null」表述；LOO 与 Q4 稳健性结果的归属存疑

**【Problem】** Stage B 4-vs-4 精确置换下界 P≈0.029 与阳性对照触及下界、HD_up 落在 P=0.80 的对比，作为「有界 null」呈现是诚实且合理的；但稿件 `:64` 把 leave-one-animal-out（Q1）与 Q4 表达匹配零分布（P=0.092）稳健性结果放在 Stage B HD_up 语境下，而提供的 `layer2_robustness.json` 实际对应的是 **HD_down**（33 个成员、diff≈0.397），并非 HD_up（11 个成员、diff=0.146）。HD_up 的稳健性数字在源产物中无法追溯。

**【Evidence】**
- `layer3b_sample_generality.json`：HD_up `diff_saline_arm`=0.1464、`p_exact_saline_arm`=0.80、`hedges_g_saline_arm`=0.219；positive control `diff`=1.2854、`p_exact`=0.028571、`hedges_g`=3.853。稿件 `:64` 报 HD_up diff +0.146 / P 0.80 / g 0.219、阳性对照 P 0.0286 / g 3.85、17.6 倍 g 差距（3.853/0.219=17.6）——均与 JSON 一致。4-vs-4 枚举 C(8,4)=70，双侧最小可达 P=2/70=0.02857，稿件与协议 §13.2「P≈0.029」正确，且 `layer2_robustness.json` 的 `Q5_nonparametric` 注释亦给出 0.029 下界。
- `layer2_robustness.json`：`n_members_present`=33，`members` 为 33 个基因（Abca7 … Thbs3），`Q3_single_gene_dominance.baseline_difference`=0.39671，`Q2_scoring_operators.mean_z.difference`=0.39671，`Q5_nonparametric.p_mann_whitney`=0.028571。这与协议 §10.6 的 HD_down（diff +0.397, P 0.0286, g 2.658）完全吻合，而 HD_up 在 `layer3b` 中仅 11 个成员、diff 0.146。`Q4_matched_null.p_empirical`=0.092091。
- 内部一致性检验：若 Q4=0.092 属于 HD_up，则 bootstrap 匹配零分布（0.092）会比主精确检验（0.80）**更显著**，构成内部矛盾；而作为 HD_down（精确 P=0.0286 已显著，bootstrap 0.092 更保守）则自洽——进一步证实该文件是 HD_down。
- 此外 LOO 的 8 个 `dropped` 条目（saline_SNI1-4、saline_sham1-4）differences 在 0.32–0.45 区间、`p_exact` 全为 0.028571，与 HD_up 的 diff 0.146 / P 0.80 完全不符，进一步佐证稳健性文件不是 HD_up。

**【Why it matters】** 孤立看，LOO 全方向保持、Q4 匹配零分布 P=0.092 本身都是合理的稳健性证据，但把它们归属于 HD_up 会使「HD_up 有界 null 稳健」的论断缺乏源产物支撑，违反协议 §11.4「每个数字必须能在 analysis/results 下定位」与稿件 Data availability 的追溯承诺。更严重的是，若把 HD_down 的 Q4=0.092 误读为 HD_up 的稳健性，会暗示 HD_up 在匹配零分布下「接近显著」（0.092），与「有界 null」叙事相左。这是一处可追溯性与潜在错归的硬伤，建议必须澄清或补产物。需要强调的是，阳性对照触及下界、HD_up 落在 0.80 这一核心「有界 null」论证本身**不依赖** Q4/LOO，因此即便 Q4 归属修正，稿件的主结论仍站得住；但稳健性陈述的可追溯性必须修复。

**【Specific fix】**
- 要么补一份针对 HD_up（11 成员、diff 0.146）的 `layer2_robustness_HDup.json`（重跑 Q1–Q5），要么将 `:64` 的稳健性陈述明确改挂到 HD_down：「HD_down 的稳健性（leave-one-out 方向保持、Q4 匹配零分布 P=0.092，见 layer2_robustness.json）支持其作为假设生成信号；HD_up 的稳健性以 Stage B 主终点与阳性对照同代码对照论证，不依赖 Q4。」并补一句说明 HD_up 在 4-vs-4 下 Q4 匹配零分布无法比主精确检验更敏感，故不另报。

### 条目 3 — [Minor–透明度]  多重比较 / BH 校正：40 项 Layer-3 检验与 7 项 Layer-3b 集合的「8/40 BH 显著」是否过度宣称

**【Problem】** 稿件 `:73` 报「40 项检验 8 项通过 BH（q<0.05），且全部在 DRG/SC/BRN、血液为 0」，作为次要发现、未过度宣称，方向正确；但需确认 BH family 定义与「全部非血液」的断言，且 8/40 的绝对规模偏小、集中在 G1/G4/G5 三套较大集合，应作为描述性而非确证性呈现。

**【Evidence】**
- `layer3_generality.json`：`n_tests`=40，`n_surviving_BH_0.05`=8，`n_sets_failing_specificity`=1。逐行核验 `q_matched_BH40`<0.05 的 8 项为：G1 DRG_CFA(0.0010)、G1 DRG_SNI(0.0010)、G1 SC_CFA(0.0010)、G1 BRN_SNI(0.0073)、G4 SC_SNI(0.0143)、G4 BRN_CFA(0.0200)、G5 DRG_SNI(0.0016)、G5 SC_CFA(0.0010)。组织分布为 DRG 3、SC 3、BRN 2、BLD 0——与稿件「全部 DRG/SC/BRN，血液 0」一致。G2 全部 q≥0.0806、G3 全部 q≥0.0652，无贡献。
- 进一步核验 BH family 规模：若 40 次检验中真实 null 比例为 1（即全部为真阴性），BH 在 α=0.05 下期望通过数约为 0.05×40×Harmonic≈0.05×40×ln(40)≈7.3；实际通过 8 项与「全部真阴性 + 偶然」的期望值接近，说明 8/40 的体量本身并不构成强确证，而更像大集合（G1 64 基因、G4/G5 ~23 基因）的边际效应经 BH 后略有显露。
- Layer-3b：`layer3b_sample_generality.json` 的 `q_BH_family_of_7` 中仅阳性对照 0.20（对应 P=0.0286，0.0286×7=0.20），无一项 <0.05；`conditions`：`a_ecm_significant_up_ge3`=false、`b_HDup_not_significant`=true、`c_positive_control_pass`=true → `verdict`=FAIL。稿件 `:78` 报「0/5 ECM 显著上调、阳性对照 g=3.85 P=0.0286、HD_up g=0.219 P=0.80」一致。协议 §13.3 的判定门槛（≥3 个 ECM 显著且上调、HD_up P>0.05、阳性对照 P≤0.05 且 g>1）逻辑自洽，条件 (a) 不满足 → FAIL，处理正确。

**【Why it matters】** 40 项中仅 8 项（20%）通过 BH，且全部出自 G1（大 matrisome，64 基因）、G4、G5 三套较大集合；在 40 次检验的 BH 框架下，这是适度的、符合「描述性次要终点」量级的结果。稿件未将其拔高为确证性发现，反而用其支撑「表达分层后已发表 ECM/力学集合保留组织特异性」——这一用法与 Layer-3 主终点 FAIL 后的 post-hoc 重定位一致，未过度宣称。唯一需澄清的是：这 8 项与 SI_g 的「4/5 保留特异性」是同一现象的两个角度，稿件应避免让读者误以为 8/40 是独立确证。Layer-3b 的 7 集合 BH 也正确未宣称任何通过，判定逻辑自洽。

**【Specific fix】**
- 在 Layer 3 节明确写出 BH family 为「5 集合 × 4 组织 × 2 模型 = 40」（稿件已隐含），并加一行：「8/40 为描述性次要结果，非预指定确证；其组织分布（DRG/SC/BRN，血液 0）与 SI_g 的 4/5 保留特异性互为印证，但不构成独立确证性证据。」

### 条目 4 — [Minor–透明度]  表达十分位匹配零分布是否真正控制了稿件归咎的「零表达混杂」；MRU 统计量的适用性

**【Problem】** 稿件 `:59` 把未分层口径的「血液比 DRG 更显著」归咎于 40–58% 位点基线零表达混杂，并称匹配零分布「修正」了该混杂。匹配零分布（仅表达基因 + 基线表达十分位分层、无放回）确实在结构上控制了「签名成员是高表达 HEK293A 基因、背景含大量零表达位点」这一混杂；但 MRU 统计量建立在 GSE111216 的 per-contrast 汇总 log2_fc（n=3）之上，匹配零分布只能控制结构性混杂，无法控制观测 log2_fc 本身的估计噪声，而这是该队列固有的效力限制。

**【Evidence】**
- `layer1_diag.json` `per_contrast`：各 contrast 的 `pct_baseline_zero` 为 BLD 58.46–58.48%、DRG 42.77%、SC 40.95%、BRN 40.46%；`signature_vs_background_baseline_KS_D`≈0.49（全 p≈0）。这与稿件 `:59` 的「40–58% 零表达、KS D≈0.49」一致，确认结构性混杂存在。
- 匹配口径 vs 未分层口径对照（HD_up）：`DRG_SNI` `p_unstratified`=0.055394 → `p_expression_matched`=0.10229（P 近乎翻倍，方向符合「去除零表达稀释后效应减弱」）；`BLD_SNI` `p_unstratified`=0.085491 → `p_expression_matched`=0.10039。说明匹配确实改变了 P，且方向与「零表达稀释」预期一致。
- MRU 定义：`MRU = median(rank)/(n_expressed−1)`，1-based，0.5=无偏移（`layer3_generality.json` `design.statistic` 与协议 §12.3）。分母 `n_expressed−1` 对 DRG_SNI 为 26827。
- 功效估算：null 下 k 个成员的中位秩方差约 1/(4k)，k=17（HD_up DRG_SNI 表达成员）时 MRU 的 SD≈0.121；观测 MRU=0.717（偏移 0.217）对应约 1.79 SD，双侧 P≈0.073 量级，与重算所得 0.102 同量级自洽，说明该统计对中等偏移敏感、对小幅/异质偏移不敏感。

**【Why it matters】** 匹配零分布的设计在原理上正确：它把随机集约束到「仅表达 + 同表达十分位」，从而消除了签名因来自高表达 FPKM>1 基因而在全背景零分布中被误判为「一致」的伪影。这一点稿件处理得当。但有两个未充分说明的局限：(a) GSE111216 只提供每 contrast 单一 log2_fc（n=3），MRU 是对一个含噪效应量的排序；匹配零分布并未降低观测噪声，因此对 n=3 per-contrast 数据的推断力本质有限——这恰是协议 §7.5 已预先承认的。(b) MRU 用中位数秩归一化到 [0,1]，对 k 个成员的中位秩在 null 下方差约 1/(4k)，k=11–64 时仍可观；DRG_SNI 观测 MRU=0.717（偏移 0.217）在 null 下 P=0.102 量级自洽，但读者应知道该统计对小幅、异质偏移不敏感，且匹配口径把 P 从 0.055 拉到 0.102 说明其更保守而非更敏锐。稿件在 Stage A 节应把这一「匹配消除了结构性偏倚但不提升 n=3 噪声下的效力」说清楚。

**【Specific fix】**
- 在 Stage A 节补一句量化声明：「匹配零分布将 HD_up DRG_SNI 的 P 由未分层 0.055 拉回至 0.102，方向与零表达稀释预期一致，证实匹配控制了结构性混杂；但该 MRU 排序建立在 n=3 per-contrast 汇总统计量之上，匹配仅消除结构性偏倚，不降低观测噪声，故 Stage A 的推断力上限仍受 n=3 限制（见 §7.5）。」

### 条目 5 — [Minor–呈现]  特异性指数 SI_g 定义与「≥4/5 失败」规则的逻辑，以及「1/5 失败 → 主终点 FAIL」的处理

**【Problem】** SI_g = |MRU(DRG,SNI)−0.5| / |MRU(BLD,SNI)−0.5|，判据 SI_g<1 即血液偏移≥DRG（特异性失败）。规则「≥4/5 失败 ⇒ 普遍性失效」逻辑自洽；「仅 1/5 失败 ⇒ 主终点 FAIL、不得宣称普遍性」的处理正确且诚实。但 SI_g 在分母 |MRU(blood)−0.5| 接近 0 时（如 G4 血液 0.499、G1 血液 0.511）会产生被放大的、不稳定的巨大值（240.5、38.4），这些头条数字应被稳定化或谨慎解读。

**【Evidence】**
- `layer3_generality.json` `per_set_specificity`：G1 MRU_target 0.9056 / blood 0.5106 / SI 38.42 / failed false；G2 0.6180 / 0.7681 / SI 0.440 / failed true；G3 0.8040 / 0.7114 / SI 1.438 / failed false；G4 0.7224 / 0.4991 / SI 240.47 / failed false；G5 0.8857 / 0.4574 / SI 9.055 / failed false。`n_sets_failing_specificity`=1，`primary_endpoint_pass`=false。稿件 Table 3（`:130-138`）与摘要 `:14` 全部吻合。
- G4 的 SI=240.5 主要由分母 |0.4991−0.5|=0.0009 驱动：DRG 偏移 0.222、血液几乎为零偏移 → 比值被极端分母放大。G1 同理（血液偏移仅 0.011）。G2 的失败是「干净」的：DRG 偏移 0.118 < 血液偏移 0.268，SI=0.44<1，是真实的方向性失败，不依赖分母大小。
- 二元判据稳健性：即便把 SI 改用「|ΔDRG| > |ΔBLD|」直接比较，G1/G3/G4/G5 仍满足（DRG 偏移 0.406/0.304/0.222/0.386 均 > 血液 0.011/0.211/0.0009/0.043），G2 不满足（0.118 < 0.268）。所以「1/5 失败」的二元结论对指标选择稳健，问题仅在连续 SI 的表面量级。

**【Why it matters】** 「≥4/5 失败 → 普遍性失效」是预先冻结的二元主终点（协议 §12.4），稿件正确报告仅 1/5 失败、主终点 FAIL，且未反向宣称「普遍性失效」，而是重定位为「签名/细胞类型特异性」——这一重定位有数据支撑（4/5 确实在 DRG 比血液偏移更大），且稿件在 Discussion 明确声明这是 post-hoc、需独立验证，符合协议 §12.6 / §13 的诚实报告要求。问题在于 SI_g 的数值呈现：240.5、38.4 这类极端值是由近零分母（血液几乎无偏移）生成的统计伪影，易被读者误读为「极强特异性」。它们不影响二元判据（只有 G2 真正失败），但作为连续量报道时不稳定、不可跨集合比较。应改用稳定化指标（如对分母加小常数，或直接报告 |ΔDRG| 与 |ΔBLD| 两列的偏移量），或明确标注「SI 为比值、分母近零时被放大」。

**【Specific fix】**
- 在 Table 3 增加两列「|ΔDRG|」与「|ΔBLD|」（即 |MRU−0.5|），并加脚注：「SI_g 为比值指标，当 |ΔBLD| 接近 0 时被放大（如 G4 |ΔBLD|=0.0009 → SI=240.5），故 SI 仅用于二元判据（SI<1），其连续大小不可跨集合比较；特异性强度以 |ΔDRG| vs |ΔBLD| 直接比较为准。」

### 条目 6 — [Minor–透明度]  预指定主终点在 Stage A→Stage B 之间的权重转移是否构成设计层面背离

**【Problem】** 协议 §3 与 §4.2 把「DRG×SNI HD_up 排名一致性」定义为唯一预指定主终点，并明确 Stage A 为排名一致性检验。v0.3 新增 Stage B（样本级 4-vs-4）后，稿件实际的「无转移」结论权重已转到 Stage B（样本级），而 Stage A 被改判为「uninformative」。这需要评估：在冻结框架内，主结论的承载从预指定主终点滑向一个后来新增的端点，是否仍可接受，还是应在 Limitations 更显式承认。

**【Evidence】**
- 协议 §3 主终点定义：「在 DRG 的 CTR → SNI 对比中，Hippo-dependent 刚度签名（HD-up）是否呈现一致的正向协同移动？」——即 Stage A 排名一致性。
- 稿件 Abstract `:14` 与 Results `:63-64` 给出的「有界 null」证据来自 Stage B（HD_up diff +0.146, P 0.80, g 0.219）与阳性对照（P 0.0286, g 3.85）；Stage A 在 `:58-59` 被定为 uninformative。即稿件的核心「无转移」结论实际上由 Stage B 承载。
- 协议 §v0.3（`:203-237`）明确 Stage B 在「Stage A 任何表达数据被审视之前」写入，且 §选择性报告声明要求 Stage A 与 Stage B 同时报告、Stage B 不得呈现为「替代」Stage A。稿件确实同时报告两者，未把 Stage B 当作 Stage A 的唯一替代，满足该声明。

**【Why it matters】** 从设计治理角度，把预指定主终点（Stage A 排名一致性）的结论让位于一个后加的、效力更低的 4-vs-4 端点，存在两层风险：(i) Stage A 的排名一致性在被「uninformative」改判后，其预指定主终点地位被实质架空；(ii) Stage B 仅 n=4/组，下界 P≈0.029，其「有界 null」的解释力上限由该低效力决定，而非由排名统计的校准决定。稿件在 Limitations `:95` 已提到「GSE261676 是 4-vs-4 设计，其精确置换下界为 P≈0.029」，但并未把「主结论的有界性主要来自 4-vs-4 低效力」作为显式声明。这一转移本身在协议允许的「同时报告、不替代」框架内可辩护，但透明度可进一步提高。

**【Specific fix】**
- 在 Limitations 增加一句：「本稿件预指定主终点为 Stage A 的排名一致性（已因 §5.3 判为 uninformative）；承载『无转移』结论的样本级证据来自 Stage B 的 4-vs-4 精确检验，其有界性（下界 P≈0.029）主要由 n=4/组的低效力决定。读者应将『无转移』理解为该设计分辨率下的有界结论，而非高效力下的确证阴性。」

## 设计层面总体可发表性判断（closing）

- **最强设计资产：** 三套对照分工（§10.5）+ 冻结框架 + 阳性对照触及 4-vs-4 下界。这使得「HD_up 是真实有界 null，而非灵敏度失败」这一核心论断在统计上站得住，且本研究是少数对纯阴性结果做了灵敏度证伪的设计。
- **必须修的设计/可追溯性缺口：** 条目 2（稳健性文件归属）。这是唯一接近「硬伤」的项：若 HD_up 的 LOO/Q4 稳健性数字无法在源产物中追溯，则违反协议 §11.4 与 Data availability 承诺。修复成本低（补产物或改挂 HD_down）。

- **未发现的致命缺陷：** 未发现 p-hacking、未发现的循环论证、未发现虚构数字或错引文献。BH 应用正确（含单调性处理），置换下界计算正确。
- **与全组面板的接口：** 本评审聚焦统计设计；关于「签名/细胞类型特异性」重定位是否构成对 §11.1 冻结主张的诚实修订（条目 5 的问题 5、§前置），属于叙事诚信层面，建议由统筹评审结合其他角色意见一并裁定，但本评审确认该重定位有数据支撑、且稿件已标为 post-hoc。

## § Stands up（我本怀疑、但复核后确认正确的点）

1. **校准口径未混用。** 稿件 `:58-59` 把匹配口径（DRG 0.102 / BLD 0.100）与未分层口径（DRG 0.597 / BLD 0.0009）分两句陈述、并明确未分层「explicitly not the primary endpoint」。我原本担心会混用，重算 `layer1_diag.json` 后确认两者在稿件中是被分隔呈现的，未违反协议 §8.1 的口径纪律。
2. **阳性对照触及 4-vs-4 下界、HD_up 落在 0.80，构成有效「有界 null」论证。** `layer3b` 显示阳性对照 diff=1.285、P=0.028571（=2/70 下界）、g=3.853，HD_up diff=0.146、P=0.80、g=0.219。同一套评分/置换代码下两者差距 17.6 倍，确实证明 HD_up 的 null 是「有界、灵敏度已验证」而非灵敏度失败。下界 0.029 与协议 §13.2 完全一致。这是本稿件最结实的设计亮点。
